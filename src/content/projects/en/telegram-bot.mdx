<Section n="03" title="Technical decisions">

<Cards>
  <Card title="The database is the source of truth">
    Instead of scheduling one job per reminder, a single job polls the database every 30s. Nothing is lost if the bot restarts, and reminders that came due while it was down are delivered on startup, flagged as late.
  </Card>
  <Card title="Business rules know nothing about Telegram">
    The service receives a `Notifier` (a `Protocol`) and works in UTC only. Handlers just translate input and output, and views are pure functions.
  </Card>
  <Card title="UTC in the database, time zones at the edge">
    A `TypeDecorator` enforces UTC even on SQLite. Conversion to `America/Sao_Paulo` only happens for display.
  </Card>
  <Card title="At-least-once delivery">
    An alert is only marked as sent after Telegram confirms delivery.
  </Card>
  <Card title="Money in cents">
    Prices are `int` cents in the database and in the rules. `Decimal` only shows up when parsing what the user typed. Never `float`.
  </Card>
</Cards>

</Section>

<Section n="04" title="Price tracking: polite and safe scraping">

The tracker reads prices from the stores' JSON-LD and sends an alert when a price reaches the target, drops by 1% or more, or when a product is back in stock.

- **Polite requests:** each product is checked every 8h (±30 min), in batches of 10, with 3–8s pauses between requests. If a store answers 403, 429 or 503, it's paused for 6h. No proxies and no captcha bypassing.
- **SSRF protection:** the bot only fetches links from allowed domains and checks the domain again after redirects, since the container shares a network with other services.
- **Private bot:** it only answers the configured `chat_id`. Anyone else is ignored, and the attempt is logged.

</Section>

<Section n="05" title="Quality and deployment">

- **101 tests** with pytest and zero network access: fake clock, store and notifier on top of an in-memory SQLite.
- **CI on GitHub Actions:** lint and formatting (ruff), tests, a check that migrations match the models, and the Docker image build.
- `main` is protected and only takes code through PRs with green checks. Every merge triggers an automatic deploy on Coolify.
- The container exposes no ports (long polling), has CPU and memory limits, and only receives secrets at runtime, never at build time.
