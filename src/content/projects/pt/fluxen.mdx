<Section n="01" title="O problema">

Controlar as finanças pessoais costuma esbarrar em dois extremos: a planilha que dá trabalho manter e os apps que fazem muito mais do que a pessoa precisa. O Fluxen é para quem quer registrar receitas e despesas e entender para onde o dinheiro está indo, com um plano gratuito que já resolve o essencial e um premium para quem quer ir além.

</Section>

<Tags items={['Stripe · assinaturas', 'Resend · e-mails', 'Coolify · deploy por push', 'VPS própria']} />

Só o frontend tem domínio público. A API fica na rede interna do Docker e é alcançada pelo proxy do nginx: mesma origem, sem CORS e com o cookie de refresh em `SameSite=Strict`.

</Section>

<Section n="03" title="Decisões técnicas">

<Cards>
  <Card title="API sem exposição pública">
    Proxy reverso no nginx em vez de roteamento por path no Traefik: menos superfície de ataque e nenhum problema de CORS.
  </Card>
  <Card title="JWT com refresh token">
    Refresh em cookie HttpOnly, detecção de reuso de token e bloqueio após tentativas de login.
  </Card>
  <Card title="Migrações versionadas">
    Esquema do banco evolui com Flyway, aplicado automaticamente a cada deploy.
  </Card>
  <Card title="Cobrança recorrente">
    Plano premium por assinatura com Stripe e limites do plano gratuito validados no backend.
  </Card>
</Cards>

</Section>

<Section n="04" title="Um bug que valeu a pena">

<Shell
  lines={[
    { cmd: 'curl https://fluxen.net.br/api/auth/login' },
    { out: 'HTTP/2 403' },
    { cmd: 'curl https://fluxen.net.br/apix' },
    { out: 'HTTP/2 403', comment: '# nem existe essa rota' },
  ]}
/>

Em produção, toda requisição para `/api` retornava 403. Parecia CORS, mas a aplicação estava saudável: testei cada camada isoladamente (API direto, nginx, proxy) e só o caminho pelo Traefik falhava. A causa era o Traefik do Coolify reservando o prefixo `/api` para o próprio dashboard. Resolvi dando prioridade ao roteador da aplicação.

</Section>

<Section n="05" title="Segurança">

Antes do lançamento, fiz uma auditoria de IDOR, autenticação, injeção e regras de negócio. Em produção: HSTS, CSP, X-Frame-Options, banco sem acesso externo, painel de deploy fechado no firewall de borda e fail2ban no SSH.

</Section>
